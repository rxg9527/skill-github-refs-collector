# 克隆超时策略

在克隆前先用 GitHub 仓库元数据里的 `size` 估算仓库体积。

## 体积来源

- 如果已知仓库地址，就请求 `GET https://api.github.com/repos/{owner}/{repo}`。
- 使用返回值里的 `size` 字段作为粗略体积信号。
- `size` 的单位是 KB，只能做启发式判断，不能当作精确的克隆耗时预测。

## 超时分档

- `size < 50MB`：`60s`
- `50MB <= size < 200MB`：`180s`
- `200MB <= size < 800MB`：`600s`
- `size >= 800MB`：`1200s`

## 回退策略

- 如果体积获取失败，默认使用 `180s`。
- 如果在选定窗口内仍未完成，就中断 clone 并等待用户指示。
- 恢复性 `fetch` 也使用同一策略，但不要超过 `300s`。
